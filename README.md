An audit agent pattern for mining payables: assay certificates and supplier
invoices are reconciled lot by lot, exceptions are priced as cash at risk,
and every decision is written into a SHA-256 hash chain that anyone can
re-verify. On 2026-10-18 the open-weight model (Qwen2.5-1.5B-Instruct via
vLLM, pinned image `vllm/vllm-openai:v0.10.2`) was served live on a Nosana
RTX 3090 deployment and stopped after the run, and the verified receipt
bundle was anchored on Arweave via the Turbo free tier. The audit +
verification layer remains fully reproducible locally without a GPU.

Built for the HackerNoon **Decentralize AI** hackathon (Round 1, deadline
Oct 31, 2026). Entry is a HackerNoon article — see `ARTICLE.md` (ready for
human review, not yet published).

## Reproduce

```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/reproduce.py     # writes results.json
python scripts/verify_chain.py  # PASS
python scripts/verify_chain.py --tamper  # FAIL (tamper demo)
pytest -q                       # 35 tests
streamlit run streamlit_app.py  # verifier UI
```

## How verification works

`expected = tonnes x contracted_price`; variance, grade and quantity
mismatches flag exceptions (see `proof_of_assay/audit.py`). Each decision
becomes a hash-chain entry: `sha256(prev_hash | index | type | canonical_payload)`.
Changing any payload breaks `verify_chain` — the Streamlit app demos this
live (tamper toggle -> FAIL).

## Honest limitations

- Data is synthetic; amounts are fixture arithmetic, not real mine documents.
- The LLM is not in the reproducibility path: rules decide, the model only
  explains/extracts. In its one live Nosana test the raw 1.5B model answered
  incorrectly (see `ARTICLE.md` / `live_evidence.json`), so it is not claimed
  to audit reliably alone.
- The Nosana deployment is stopped, not a running service. The Arweave
  anchor is live: https://arweave.net/yTIbmFhgUS88RNaO2W92Oy7kPigpMyRUmToOeumLSus
